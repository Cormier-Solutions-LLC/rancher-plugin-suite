# Network Manager design compliance audit

**The audit and remediation plan are complete. The application does not yet fully follow the design standard.** This is an assessment, not a completed remediation or native-release certification.

I reviewed all **13 registered routes**, visually inspected the ten main pages and the three hidden operation pages, and inspected editor, selection, restore, merge, help and snapshot-capture states. There are **62 screenshots**, **57 recorded UI states**, and a requirement-by-requirement assessment of **231 indexed source items**: 9 reference pointers and 222 requirements/checklist items.

The most consequential findings are snapshot correctness and mutation safety: namespaced issuer profiles can collide during merging, persistent metadata changes can be missed, proposed configuration can enter the pre-change capture source, and the snapshot deletion endpoint accepts a recent recovery copy without establishing complete affected-content coverage. Visual inconsistencies include mobile document scrolling, wrapped heading controls, Rescan sizing, panel-level workflow actions, blue Cancel buttons, missing owning navigation on hidden pages, the Settings URL field, and duplicated Help dividers.

## Evidence and method

The governing source is the pinned [RANCHER-PLUGIN-DESIGN.md copy](RANCHER-PLUGIN-DESIGN.audit-source.md), with normalized UTF-8/LF SHA-256 `bd99fea45a6fc56b1360d47d1cd477e3d277631fd12be23c6ed5a3b95efe2d8a`. The [full checklist](checklist.md) quotes each indexed requirement and provides its result, analysis and evidence. [assessment.json](assessment.json) is the machine-readable counterpart; [requirements.json](requirements.json) preserves source lines/sections. The matrix includes the newly added suite/global Git LFS demo-data requirements rather than silently omitting them.

Tests ran against an isolated built preview at `127.0.0.1:8091`, with its own project-local snapshot directory and synthetic merge records. Browser actions used the supported Codex browser adapter; DOM evaluation only measured rendered content. The user's `8088` preview and live Rancher configuration were not changed. No live apply, deletion, merge submission, certificate issuance, credential replacement or installed-cluster restore was executed.

All ten main pages were measured at **1920×1080, 1280×720, 800×700 and 600×800**. Each main page was visually inspected at 1280×720; representative wide/narrow views and all named workflow screenshots were also inspected. All primary table rows were measured at 1280px; responsive recordings initially sampled up to five ordinary rows per table. These checks establish geometry for those datasets/viewports, not pixel-perfect behavior for every possible dataset. [browser-environment.json](browser-environment.json) records observed asset URLs. The current preview build also compiled successfully.

The audit deliberately distinguishes local UI/source/test evidence from installed and live behavior. It does not mark an authenticated backend, all controller replicas, host theme inheritance, Helm installation, traffic continuity, actual service-account quota or live recovery as verified merely because preview code exists.

## Tests created and executed

The new UI tests assert actual rendered geometry instead of snapshotting component implementation details. A pure detector unit suite validates both good and deliberately bad layouts; a recorded-browser suite applies that detector to the measured real application. The latter intentionally remains red for current application defects. It **does not launch a new browser when replayed**; fresh captures must be collected after fixes.

| Command | Result | What it establishes |
|---|---|---|
| `npm run test:ui:contracts` | **10 passed** | Detector recognizes misalignment, overflow, button/icon/count and header problems; not application compliance by itself |
| `npm run test:ui:audit` | **27 passed, 30 failed**, 57 states | Real recorded application states violate geometry/action contracts; failures were not skipped or weakened |
| `npm run test:audit:snapshots` | **0 passed, 2 failed** | Actual merge model reproduces namespaced issuer collision and missed persistent-label change |
| `npm run test:configuration` | **Passed** | Existing model tests including port mapping, namespace immutability, certificates, snapshot gate, Secret freshness/presence, refresh and bounded reads |
| `npm run test:snapshots` | **3 passed** | Existing local server suite: ZIP encryption/recovery, verification, merge, mounted storage/quota, restart and cleanup; includes cross-plugin server coverage |
| `npm run build:preview` | **Passed** | Current standalone assets compile; this does not prove install/live readiness |

The 30 failed UI states include repeat observations of the same problem at different pages/viewports. They are not 30 unique root causes. Primary 1280px captures only fail Port Configurations' Rescan typography/width; narrower views and workflow states reveal the other measurable failures. Tests cannot automatically detect every semantic/color/ownership issue in the report.

## Ordered implementation plan

This plan is ready for review. Its work is pending; audit completion does not mean the following fixes have been implemented.

1. **Correct snapshot identity/content/current-state boundaries and destructive server checks** — F16–F19. Make both new regressions pass, add persisted-before/proposed-after coverage tests and reject deletion with an unrelated recent backup. Re-run encryption/recovery/merge/cleanup suites. Establish one explicit authoritative confirmed-state model before expanding live writes.
2. **Make the shared shell and page actions conform** — F01–F09, F11–F14, F23–F25, F27. Fix mobile height/nav, header/count grouping, Rescan sizing, secondary Cancel, hidden owning navigation, consistent fields/dividers/generation filter, scoped loading/dependencies and direct fix links. 3. **Complete fixture and adapter coverage** — F10/F21/F22/F26. Add missing representative feature states to the shared scrubbed LFS source and UI tests, verify no-credentials/no-Docker startup and optional-backend failure behavior, and provide current-settings integration tests. Verify counts/colors/filter semantics against populated, empty, warning, missing-dependency and error cases.
4. **Validate the native plugin separately** — F15/F20 and all NOT_VERIFIED acceptance items. In an authorized test Rancher environment, verify real native navigation/global namespace/theme inheritance, permissions, controller replicas, backend revision/ownership validation, Apply/process/readback, failure recovery and managed-service continuity. 5. **Close the compliance review** — update the same standards/evidence links, regenerate the item matrix and report only remaining approved variations or concrete limitations. No known failure should become a passing test merely through a weaker detector.

No new standards conflict needs an implementation decision for this audit. The existing right-side navigation count variation is explicit. Any conflicting design alternative discovered during remediation should be presented with the concrete affected requirement and proposed result before it is substituted.

## Limits and retained evidence

The complete native plugin was not installed in a test Rancher cluster during this audit. Browser Back/reload/unload guards, full keyboard traversal, full theme/accessibility contrast, encrypted browser merge with real credentials, backend failure focus restoration, permission matrices, actual live processes/controller logs, independently backed-up PVC storage, LFS feature completeness and release lifecycle remain unverified where called out. Source existence and earlier transcript claims are not substituted for those checks.

Only audit documentation, tests and npm test entry points were added for this request. Existing dirty application and sibling-project changes were preserved. No fixes, release, Docker replacement or live cluster mutation are claimed. The isolated audit server/tab are closed at completion; screenshots, synthetic records and test logs remain available locally for review.
